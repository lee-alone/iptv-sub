# IPTV M3U 聚合器 Go 重构 - 快速参考

## 项目信息

- **项目名称**：IPTV M3U 聚合器 Go 重构
- **源语言**：Python（Flask + APScheduler）
- **目标语言**：Go 1.21+
- **预计周期**：8 周
- **主要目标**：性能提升 3-5 倍，改进并发处理

## 核心组件

| 组件 | 职责 | 关键方法 |
|------|------|---------|
| **SubscriptionManager** | 管理订阅源 | Add/Get/Update/Remove/Save/Load |
| **M3UParser** | 解析 M3U 文件 | FetchM3U/ParseM3U |
| **ChannelAggregator** | 聚合和去重频道 | AggregateChannels/GetAll/Save/Load |
| **StreamTester** | 测试流可用性 | TestStream/BatchTest |
| **Scheduler** | 执行周期性任务 | AddJob/RemoveJob/TriggerJob/Start/Stop |
| **ChannelExporter** | 导出 M3U/JSON | ExportM3U/ExportJSON/SaveExport |
| **ConfigManager** | 管理配置 | Load/Save/Validate |

## 并发策略

### 流测试并发
```
主线程
  ├─ 工作线程 1 (测试 URL 1-10)
  ├─ 工作线程 2 (测试 URL 11-20)
  ├─ 工作线程 3 (测试 URL 21-30)
  └─ 工作线程 N (测试 URL N*10-N*10+10)
```

### 数据访问并发
```
多个 goroutine
  ├─ 读取频道数据 (sync.RWMutex 读锁)
  ├─ 更新频道数据 (sync.RWMutex 写锁)
  └─ 保存到磁盘 (原子写入)
```

## 关键决策

### 1. 为什么选择 Gin？
- 高性能（比 Flask 快 10-50 倍）
- 最小开销
- 优秀的路由和中间件

### 2. 为什么选择 robfig/cron？
- 轻量级
- 支持 cron 表达式
- 易于集成

### 3. 为什么选择 JSON 文件存储？
- 与 Python 版本兼容
- 易于备份和迁移
- 无需数据库

### 4. 为什么使用工作池模式？
- 限制并发数量
- 防止资源耗尽
- 易于控制和监控

## 常见问题

### Q: 为什么不使用数据库？
A: JSON 文件存储与 Python 版本兼容，易于备份和迁移。对于这个应用的规模，性能足够。

### Q: 如何处理并发写入？
A: 使用 sync.RWMutex 保护共享数据，使用原子写入防止文件损坏。

### Q: 如何处理流测试超时？
A: 使用 context.WithTimeout 实现超时控制，超时后立即返回。

### Q: 如何处理 HLS 流循环？
A: 实现深度检查，检测 HLS 流的循环和卡顿。

### Q: 如何从 Python 迁移？
A: 并行运行两个版本，共享数据目录，验证一致性后切换。
