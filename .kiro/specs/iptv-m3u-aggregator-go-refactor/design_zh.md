# 设计文档：IPTV M3U 聚合器 Go 重构

## 概述

IPTV M3U 聚合器正在从 Python（Flask + APScheduler）重构为 Go，以改进性能、并发处理和部署特性。Go 版本与 Python 版本保持功能对等，同时利用 Go 在并发 I/O、静态编译和高效资源利用方面的优势。

### 关键设计目标

1. **性能**：通过原生并发减少流测试和聚合的延迟
2. **可扩展性**：高效处理数千个频道和并发请求
3. **可维护性**：清晰的关注点分离和明确定义的接口
4. **兼容性**：与 Python 版本保持数据格式兼容性以实现无缝迁移
5. **可靠性**：在故障条件下进行健壮的错误处理和优雅降级

## 核心组件

### 1. 订阅管理器

**职责**：管理订阅源（CRUD 操作、持久化）

主要功能：
- 添加/删除/更新订阅源
- 管理订阅状态（活跃、失败、未测试）
- 持久化到 subscriptions.json
- 启动时加载订阅

### 2. M3U 解析器

**职责**：从远程源获取和解析 M3U 文件

主要功能：
- 从 URL 获取 M3U 文件（支持超时）
- 解析 EXTINF 元数据和频道 URL
- 提取 tvg-id、tvg-name、tvg-logo、group-title
- 处理格式错误的内容
- 关联源 URL 用于跟踪

### 3. 频道聚合器

**职责**：合并来自多个源的频道并去重

主要功能：
- 合并来自多个源的频道
- 基于名称或 tvg-id 检测重复
- 计算名称相似度（Levenshtein 距离）
- 合并重复频道并保留所有 URL
- 持久化到 channels.json

### 4. 流测试器

**职责**：测试频道 URL 的可用性和响应性

主要功能：
- 并发测试多个 URL（工作池模式）
- 记录响应时间和状态
- 支持深度检查（HLS 流验证）
- 检测 HLS 流循环和卡顿
- 识别每个频道的工作 URL

### 5. 调度器

**职责**：执行周期性任务（更新、测试）

主要功能：
- 基于 cron 表达式安排任务
- 支持手动触发
- 优雅关闭
- 任务序列化防止冲突

### 6. 导出器

**职责**：生成 M3U 和 JSON 导出

主要功能：
- 生成有效的 M3U 文件
- 生成 JSON 导出
- 支持仅导出在线频道
- 管理导出文件列表
- 删除导出文件

### 7. 配置管理器

**职责**：加载、验证和持久化配置

主要功能：
- 从 config.json 加载配置
- 使用合理的默认值
- 验证配置值
- 支持环境变量覆盖
- 持久化配置更改

## 并发策略

### 流测试并发

- 使用工作池模式，可配置工作者数量（默认 10）
- 每个工作者从共享队列处理频道
- 频道并发测试，结果聚合
- 支持上下文取消以优雅关闭

### Web 请求并发

- Gin 框架原生处理并发请求
- 每个请求在自己的 goroutine 中处理
- 使用 sync.RWMutex 保护共享数据访问
- 使用原子写入防止文件损坏

### 后台任务并发

- 调度器在单独的 goroutine 中运行周期性任务
- 更新和测试任务序列化防止冲突
- 支持任务取消

## 错误处理

### 错误分类

1. **网络错误**：超时、连接拒绝、DNS 解析失败
   - 操作：记录、标记为失败、继续处理

2. **解析错误**：格式错误的 M3U、无效的 JSON
   - 操作：记录、跳过无效条目、继续处理

3. **文件 I/O 错误**：权限拒绝、磁盘满、文件未找到
   - 操作：记录、尝试重试（指数退避）

4. **配置错误**：无效的配置值
   - 操作：记录、使用默认值、继续

5. **并发错误**：竞态条件、死锁
   - 操作：通过适当的同步防止

### 日志策略

- 使用结构化日志（slog）
- 日志级别：DEBUG、INFO、WARN、ERROR
- 日志格式：时间戳 | 级别 | 组件 | 消息 | 上下文
- 输出到 stdout 和可选的文件

## 数据持久化

### JSON 数据格式

**subscriptions.json**：订阅源列表
- url：订阅源 URL
- name：订阅源名称
- enabled：是否启用
- status：当前状态
- channel_count：频道数量
- last_updated：最后更新时间

**channels.json**：聚合频道列表
- id：唯一频道 ID
- name：频道名称
- group_title：分组
- tvg_id、tvg_name、tvg_logo：电视指南元数据
- urls：所有可用的 URL 列表
- source_urls：URL 到源的映射
- test_results：测试结果

**config.json**：系统配置
- port：服务器端口
- request_timeout：请求超时
- stream_test_timeout：流测试超时
- max_test_workers：最大并发工作者
- update_interval：更新间隔
- test_interval：测试间隔
- match_by：匹配策略
- similarity_threshold：相似度阈值
- deep_check：是否启用深度检查

## 正确性属性

### 属性 1：订阅持久化往返

对于任何具有有效 URL 和元数据的订阅，当添加到系统然后从磁盘加载时，加载的订阅应具有与原始订阅相同的属性。

**验证**：需求 1.1、1.6、10.1、10.4

### 属性 2：M3U 解析完整性

对于任何有效的 M3U 文件内容，解析应提取所有 EXTINF 行和 URL 而不丢失，提取的频道数应等于源中的 EXTINF 条目数。

**验证**：需求 2.2、2.3、2.6

### 属性 3：频道聚合幂等性

对于任何频道集合，聚合两次应产生与聚合一次相同的结果（相同的频道计数、相同的去重）。

**验证**：需求 3.1、3.2、3.3

### 属性 4：流测试一致性

对于任何标记为"在线"的频道 URL，在短时间窗口内的后续测试也应将其标记为"在线"（假设没有网络变化）。

**验证**：需求 4.2、4.3、4.4

### 属性 5：导出格式有效性

对于任何频道集合，导出为 M3U 格式然后解析导出的 M3U 应产生与原始频道等效的元数据（往返属性）。

**验证**：需求 6.1、6.2、13.4

### 属性 6：配置持久化

对于任何配置修改，当保存然后加载时，加载的配置应具有与保存的配置相同的值。

**验证**：需求 9.3、9.4、10.3

### 属性 7：并发请求隔离

对于任何并发 Web API 请求，每个请求应接收一致的数据快照而不受其他并发请求的干扰。

**验证**：需求 11.2、11.3

### 属性 8：聚合后数据一致性

对于任何聚合操作，持久化的频道数据应与内存中的频道数据匹配，确保保存操作期间不丢失数据。

**验证**：需求 3.4、10.2、10.6

### 属性 9：向后兼容数据格式

对于由 Python 版本创建的任何 subscriptions.json、channels.json 或 config.json 文件，Go 版本应成功加载和解析它而不丢失数据。

**验证**：需求 13.1、13.2、13.3

### 属性 10：调度器任务执行

对于任何计划的任务，当手动触发时，它应立即执行并成功完成，当定期计划时，它应在配置的时间间隔执行。

**验证**：需求 5.2、5.3、5.4、5.5

## 性能优化

### 流测试优化

- 实现 HTTP 客户端连接池
- 使用 HEAD 请求进行初始连接检查
- 实现基于超时的早期终止
- 缓存 DNS 查询
- 批量测试同一频道的多个 URL

### 内存优化

- 流式处理大型 M3U 文件而不是完全加载到内存
- 原地实现频道去重以减少内存使用
- 使用 sync.Pool 处理临时对象
- 为大型操作实现垃圾回收提示

### 磁盘 I/O 优化

- 批量写入操作
- 使用原子写入防止损坏
- 为大型数据集实现增量保存
- 缓存文件修改时间以检测外部更改

## 部署考虑

### 单二进制部署

- 编译为单个可执行文件，包含嵌入的静态文件
- 无需外部依赖
- 易于部署到 Docker、VM 或裸机

### 配置

- 支持环境变量覆盖配置
- 支持命令行标志
- 支持 config.json 文件用于持久配置
- 优先级：CLI 标志 > 环境变量 > config.json > 默认值

### 监控

- 暴露 Prometheus 指标端点
- 跟踪：请求计数、延迟、错误率、频道计数、在线百分比
- 为负载均衡器提供健康检查端点

## 从 Python 的迁移路径

### 阶段 1：并行部署

- 在 Python 版本旁边运行 Go 版本
- 共享数据目录（subscriptions.json、channels.json、config.json）
- 验证版本之间的数据一致性

### 阶段 2：切换

- 停止 Python 版本
- 验证 Go 版本拥有所有数据
- 将流量切换到 Go 版本

### 阶段 3：清理

- 归档 Python 版本
- 删除 Python 依赖
