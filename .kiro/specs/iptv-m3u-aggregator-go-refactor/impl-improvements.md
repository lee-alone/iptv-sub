## 每日工作流建议

### TDD 循环
```
1. 写测试（单元测试）
2. 实现功能
3. 运行测试
4. 重构代码
5. 提交代码
```

### 示例：M3U 解析器开发

**Day 1：**
```bash
# 上午：写测试
touch parser_test.go
# 编写 ParseM3U 的单元测试用例

# 下午：实现基础功能
touch parser.go
# 实现 ParseM3U 函数

# 晚上：运行和修复

go test -v ./services/parser
```

**Day 2：**
```bash
# 上午：完善功能和边界情况
# 处理空行、注释、格式错误等

# 下午：性能测试

go test -bench=. -benchmem ./services/parser

# 晚上：重构优化

gofmt ./services/parser
go vet ./services/parser
```

## 风险缓解计划

### 风险 1：性能不达预期
**缓解措施：**
- ✓ 第 4 周进行首次性能基准测试
- ✓ 第 7 周留出专门优化时间
- ✓ 如果性能目标未达成，调整目标或优化方案

### 风险 2：并发问题
**缓解措施：**
- ✓ 使用 go test -race 进行竞态检测
- ✓ 每周运行并发场景测试
- ✓ 使用静态分析工具（go vet, staticcheck）

### 风险 3：数据兼容性
**缓解措施：**
- ✓ 第 2 周就导入真实数据进行测试
- ✓ 第 7 周进行完整的兼容性测试
- ✓ 准备数据迁移脚本

### 风险 4：开发进度延迟
**缓解措施：**
- ✓ 每周进行进度审查
- ✓ 设定最小可行功能（MVP）
- ✓ 如果延迟，优先保证核心功能

## 质量门禁

### 代码提交前
```bash
# 格式化
go fmt ./...

# 静态检查
go vet ./...

# 单元测试
go test ./... -cover

# 竞态检测（关键模块）
go test -race ./services/...
```

### 合并到主分支前
```bash
# 所有测试通过
go test ./... -v -cover

# 构建成功
go build -o iptv-aggregator

# 集成测试通过
go test ./tests/integration/...

# 代码审查通过（至少 1 人）
```
